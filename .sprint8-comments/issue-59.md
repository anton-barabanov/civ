## Дизайн-ревью (архитектор) — S8-4 Баланс-проход по симуляциям, волна 4a из 5 (СТРОГО после #58 — бейзлайн на карте 36×24; параллельно #60 — файлы не пересекаются; → #61)

РЕШЕНИЕ ВЛАДЕЛЬЦА ПРОДУКТА (обязательно): тюнинг ТОЛЬКО констант (числовых значений) в core.js. Без изменения механик, ветвлений, порядка вызовов и ИИ-поведения: новые условия/предикаты/перестановки запрещены, даже «маленькие».

### Ключевые решения

1. **Харнесс**: отдельный скрипт `test/balance.mjs` — НЕ в suite (test/run.mjs его НЕ вызывает, времени в бюджет 60с не добавляет). Запуск: `node test/balance.mjs [--games=50] [--diffs=0,1,2] [--seed=N]`. DOM-заглушки — копия run.mjs:1-26; импорт app.js → debugApi (как в run.mjs:65-66). Воспроизводимость: патч Math.random детерминированным LCG с сидом из CLI (образец фиксации Math.random уже используется в run.mjs-сценариях).
2. **Сценарий ИИ×ИИ без правок core.js**: `newGame(diff, 5, 1)`, затем `api.S.players.forEach(p => p.isHuman = false)` (S открыт через debugApi) — так «человек 0» становится ИИ, ноль диффа в core.js. Цикл `while (!api.S.over && api.S.turn < 300) api.endTurn();` (endTurn уже экспортирован). 50 партий × 3 сложности (0/1/2) = 150 прогонов на итерацию.
3. **Метрики** (снимаются в harness, не в core): медиана ходов победы; распределение типов побед (conquest/culture/space/diplomacy/лимит); ВВП игрока 0 = Σpop по ходам, профиль до хода 100 (профиль игрока-«человека» как прокси стартовой позиции); доля банкротств ИИ (доля ходов с gold===0 по всем ИИ); число объявленных войн и миров на партию; число городов с религией к ходу 100.
4. **Вывод**: `/tmp/civ-balance/{baseline|iter-N}-diff{0,1,2}.json` + `summary.csv` (ходы/типы/ВВП100/банкротства/войны) — до и после каждой итерации; финальный отчёт приложить комментарием к задаче.
5. **Кандидаты констант** (только числа в core.js): подать «3» в cityYields (1143); содержание в playerGoldPerTurn (1151: `cities.length * 2 + units*1` — два числа); цены поздних чудес (WONDERS:71-82, 130-200) и поздних юнитов; CULTURE_WIN_THRESHOLD (160); BARB_SPAWN_EVERY (55) / BARB_AGGRO (56); aiDiplomacy-пороги: вероятность войны `0.05 + 0.25 * (si/sj - 1)` и кэп 0.5 (2426), PEACE_STRENGTH (48), TRADE_COOLDOWN (49).
6. **Процесс**: ОДНА константа за итерацию → полный прогон 150 партий → сравнение с baseline → фиксация или откат, обоснование метрикой до/после в комментарии задачи. Итог: 5-10 констант. Инварианты после каждой итерации: `node test/run.mjs` полностью зелёный; распределение побед — ни один тип <15% и не >50%; человек-на-старте не в безнадёжной позиции (доп-прогон: 1 человек × 3 ИИ, seed-фиксированный, ВВП человека к ходу 50 ≥ ~0.8× лучшего ИИ + короткий ручной плейтест).
7. **Критичное про якоря мутаций**: часть кандидатов лежит ВНУТРИ строк-целей мутаций test/run.mjs:38-54 — подать «3» (мутация e: `3 + Math.floor(c.pop / 2) + tradeGold`), BARB_SPAWN_EVERY (n), democracy 1.25 (m). Правило: изменение такого числа — ТОЛЬКО атомарно вместе с обновлением MUT_TARGETS и ожиданий проверок в том же коммите (например, e: строка цели + проверка run.mjs:1385 `gold === 3`); семантика мутации сохраняется (мутированное значение остаётся детектируемо неверным). Пороги 0.6 выборов (k) и 0.5 mapValue (l) — исключить из кандидатов первой очереди именно из-за якорей.
8. **Что НЕ делать**: не пересобирать формулы (upkeep, cityYields), не менять порядок волн endTurn/processEconomy, не заводить новые константы поведения (вынос литерала в именованную константу БЕЗ изменения значения — допустим для читаемости, диф поведения нулевой).

### Порядок правки (мерж-точки)
test/balance.mjs (новый, единственный новый файл) → прогон baseline → итерации: правка ОДНОГО числа в core.js (+синхронно MUT_TARGETS/ожидания, если якорь) → прогон → фиксация. core.js диф в финале — только числа в строках 48-56, 71-82, 1143, 1151, 160, 2426.

### Запреты мутаций (a-o)
- **e/m/n**: числа внутри целей мутаций — только атомарно с MUT_TARGETS (п.7).
- **b/d**: processEconomy-хвост и пара aiDiplomacy/aiTurn — не задеты (константы, не вызовы).
- **k/l**: пороги 0.6/0.5 в processElections/mapValue — не кандидаты.
- **a/c/f/g/h/i/j/o**: амбар, пирамиды, кулдаун, счастье, ферма, дороги, purge, шпион — не задеты.

### Риски
- Переобучение под ИИ-мету: обязательная человек-метрика (1×3) + ручной плейтест финальных значений; A/B на фиксированном сидe, финал — медиана по 3 сидам.
- Время: оценка — партия ~200-300 endTurn по несколько мс ≈ 1-2 с; 150 партий ≈ 3-5 минут на итерацию — приемлемо; при выходе за рамки сократить games до 30 на промежуточных итерациях, финал на 50.
- Рассинхрон тестов при правке якорных чисел — процесс п.7 (атомарность) обязателен, иначе suite падает на мутационных проверках.

УПРОЩЕНИЯ ВЛАДЕЛЬЦА ПРОДУКТА (перекрывают тело issue): растущий по прогрессу/каркасный меш НЕ делаем (прогресс уже виден полоской производства #55 — prodRatio в vm, renderer3d:485-496); вместо этого — scale-in при завершении, пульс полоски при активном производстве, кольцо-импульс при завершении чуда.

### Ключевые решения

1. **(a) Scale-in 0.6 с при завершении постройки** — образец spawnT юнитов (renderer3d:633-636, масштаб 0.05→1; у городов аналогично 643-647, но там 0.3 с — НЕ дублировать на город-холдер):
   - Чудо завершено: новый wMesh (models3d.createWonderMesh:430, вешается в syncEntities:463-469) появляется с анимацией масштаба 0.05→1 за 0.6 с — таймер `buildT` в записи cityHolder, тикает в frame() рядом с городским spawnT (642-647). Плюс кольцо (см. п.3).
   - Обычное здание завершено: отдельных мешей у зданий НЕТ (createCityMesh:373 рисует дома по pop и стены; отдельный меш только у чудес) — one-shot «пульс» города-холдера: scale 1→1.12→1 за 0.6 с (таймер `pulseT`), без перестройки меша.
   - Детект завершения: сравнение с прошлым draw — в app.js buildViewModel (76-83) добавить в vm.cities ДВА поля-числа: `buildings: c.buildings.length` и `wonders: c.wonders.length` (wonders-строка 81 уже есть — добавить длину). Рост числа → запуск таймера. Это ЕДИНСТВЕННОЕ касание app.js (vm-поля, никакой логики) — осознанное исключение из «renderer3d/models3d только», без него детект невозможен (renderer состояние S не видит).
2. **(b) Пульс полоски при активном producing**: в frame() для городов с prodRatio ≠ null: `barFill.scale.x = max(0.02, ratio) * (1 + 0.06 * sin(t*3 + cityId))` — модуляция масштабом, БЕЗ клонирования материала (prodBarFillMat:345 общий на все города). Полоска скрыта при отсутствии производства (494-495 уже гейтят видимость) — пульса нет. Кран/леса/жёлтая точка над городом — НЕ делать (дубль #55).
3. **(c) Кольцо-импульс при завершении чуда**: реюз spawnRing (352-366) — spawnRing(tileX(c.x, vm), tileZ(c.y, vm), 0xffe14d, 0.45); лимит FX_MAX=5 (10) уже защищает от спама.
4. **Сейв mid-construction**: персистентных «строительных» мешей нет — критерий тела issue «масштаб соответствует остатку при загрузке» закрывается тривиально (синхронизировать нечего; WIP-видимость = полоска #55, она рендерится из состояния и корректна после load). Зафиксировать в PR-описании как осознанное упрощение.
5. **Производительность**: 2-3 float-таймера на город, ноль аллокаций в кадре (все объекты уже в cityHolders); городов немного даже на 36×24 (#58) — дёшево. Совместимость с инстансингом #58: таймеры живут в overlayRoot/cityHolders, слой тайлов не трогаем.
6. **Кликабельность**: пикинг идёт по тайл-мешам (pick по плитам/декору, renderer3d:118-130), не по городам — scale-анимации pick-поверхность не меняют; критерий «не мешает кликам/тултипам» выполняется без правок.
